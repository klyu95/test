# InsureFlow 기획서
> EDI 4대보험 자료 → 급여 공제 양식 자동 입력 Windows 프로그램 (승인 후 `docs\InsureFlow_기획서.md`로 저장)

## 1. 배경 및 목적
- **문제**: 매월 EDI(국민연금·고용보험·건강보험)에서 받은 3개 원본을 직원별로 눈·수작업 대조해 급여 공제 양식(`1번.xls`)에 옮기고 있다. 직원 약 58명 × 공제 8칸이라 오입력·누락·건강/요양 근로자 몫 계산 실수 위험이 크다.
- **목표**: 파일 4개만 선택하면 이름 매칭 → 근로자 부담액 산출 → 미리보기 → 확인 → 새 `.xls` 저장까지 끝내고, 예외(동명이인·미매칭·누락)와 보험별 합계 검증 보고서를 제공한다.
- **성공 기준**: ① 대상 양식의 직원·순서·사번·기타 공제값·서식이 한 글자도 바뀌지 않는다. ② 입력 8개 칸이 원본과 보험별로 합계 일치한다(차이는 보고서에서 사유 설명 가능). ③ 월 작업시간 수십 분 → 수 분.

## 2. 입력 파일 분석 (실제 샘플 `docs\` 기준)
| 구분 | 파일 | 형식 | 구조 | 이름 열 |
|---|---|---|---|---|
| **대상 양식** | `1번.xls` | BIFF .xls | 시트 `(2026-09) 공제 근로자별 변동자료`, 1행 헤더, 2~59행 직원 58명, A=사번 B=성명 C~T 공제 18항목(대부분 빈칸) | 성명 |
| 국민연금 | `2차결정내역통보서_…xlsx` | xlsx | 3행 헤더, 4행~ 58명, 합계행 없음 | 성명 |
| 고용보험 | `당월보험료부과내역조회(고용)_…xlsx` | xlsx | **1~2행 2단 헤더**, 3행~ 51명, 마지막 `합계` 행 | 근로자명 |
| 건강·요양 | `보험료_고지(산출)_내역서_…xls` | BIFF .xls | 1행 헤더, 2행~ 59명, 합계행 없음 | 성명 |

### 입력 대상 칸 ↔ 원본 매핑 (8칸만 입력, 나머지 10칸은 불변)
| 대상 양식 열 | 값(근로자 부담분만) | 원본 컬럼 |
|---|---|---|
| 국민연금[03] | 당월분 본인기여금 | NP `당월분_(본인기여금)` |
| 국민연금정산[09] | 소급분 본인기여금 (음수 가능) | NP `소급분_(본인기여금)` |
| 고용보험[05] | 해당월 ① 근로자 실업급여보험료 | EI `산정보험료(해당월①)/근로자실업급여보험료` |
| 고용보험정산[25] | ② 재산정 + ③ 정산의 근로자 실업급여보험료 | EI `재산정보험료②` + `정산보험료③` (근로자 열) |
| 건강보험[04] | 당월 산출보험료 근로자 몫 | HI `산출보험료` ÷2 |
| 건강보험정산[10] | (정산금액 + 연말정산) 근로자 몫 | HI `정산금액` + `연말정산` ÷2 |
| 장기요양보험[22] | 요양산출보험료 근로자 몫 | HI `요양산출보험료` ÷2 |
| 장기요양보험정산[23] | (요양정산보험료 + 요양연말정산보험료) 근로자 몫 | HI `요양정산보험료` + `요양연말정산보험료` ÷2 |

핵심 규칙(샘플 검증으로 확정):
- **건강·요양은 총액(사업주+근로자)만 제공** → 근로자 몫 = `총액÷2` 후 **10원 미만 절사**(0 방향). 사업주 몫 = 총액 − 근로자 몫(보고서 검증용). *(사용자 확정)*
- 건강 `고지금액 = 산출 + 정산`, `가입자총납부 = 고지 + 연말정산` → **당월분은 `산출`, 정산분은 `정산 + 연말정산`** 으로 분리(고지금액을 당월에 넣으면 정산이 섞임).
- 정산 합산 후 한 번만 ÷2·절사(개별 절사 누적 오차 방지).
- 고용보험은 **근로자 실업급여보험료만**(사업주 실업급여·고안직능은 제외). `합계` 행은 데이터에서 제외하되 검증 기준으로 사용.
- 음수(환급)는 부호 그대로 반영. 0원은 0으로 입력(데이터 존재), 원본에 행이 없으면 빈칸 유지.

### 샘플에서 발견된 예외 사례 (설계에 반영)
- 대상 58명 중 **고용보험 자료에 없는 7명** → 빈칸 + 확인 대상(비대상 임원 등 가능성). *(사용자 확정)*
- 건강보험 자료에만 있는 1명(대상 양식에 없음) → **추가하지 않고** 보고서 "대상 외 원본 직원"에 기록.
- 상실(퇴사)자: 국민연금은 금액 공란, 건강·고용은 퇴직정산만 존재(당월 0, 정산분만) → 당월/정산 분리 로직 필요.
- 건강/요양 정산 음수(요양 −70,960 등), 연말정산 양수(건강 8,880 등)가 실제 존재.
- 샘플은 동명이인 없음·국민연금 소급분 전원 공란 → **합성 테스트 데이터**로 해당 경로 검증 필요.

## 3. 기능 요구사항
1. **파일 선택**: 4개 슬롯(대상 양식 / 국민연금 / 고용보험 / 건강·요양). 드래그&드롭 지원, 헤더 문구로 파일 종류 자동 판별(슬롯 오배치 시 경고). 고지년월(2026-09 / 202609)과 대상 시트명의 월이 다르면 경고.
2. **이름 매칭**(이름 정규화: 공백·NBSP 제거): 대상 양식 직원만 처리, 순서·사번·성명 불변.
   - 동명이인: 원본 또는 대상 쪽에 같은 이름이 2건 이상 → **자동 입력 금지**, 후보(주민번호 뒷자리 마스킹, 취득일, 금액)를 보여주고 사용자가 선택하거나 보류.
   - 교차검증: 3개 원본의 주민번호(내부 비교 전용)가 서로 다르면 동명이인/오매칭으로 간주해 확인 대상.
   - 미매칭·자료 누락: 해당 칸 빈칸 + 확인 대상.
3. **입력 미리보기**: 직원 × 8칸 표. 상태 색상(정상 / 확인 대상 / 자료 없음), "확인 대상만 보기" 필터, 변경 칸 강조, 음수 빨간 표시, 직원 클릭 시 산출 근거(원본 값·÷2·절사) 패널.
4. **확인 단계**: 요약(처리/확인 대상/미반영 건수), 보험별 합계 검증 표, 확인 대상 항목 체크 후에야 저장 가능(체크 안 한 동명이인은 미입력 상태로 저장됨을 명시).
5. **저장**: 항상 **새 파일**(`원본명_InsureFlow_YYYYMMDD_HHmm.xls`). 원본과 같은 경로 거부. 저장 후 폴더 열기 버튼. 동일 폴더에 **검증보고서(.xlsx)** 동반 생성.
6. **보험별 합계 검증 보고서**(화면 + 파일): 국민연금·고용·건강·장기요양 각각 `원본 근로자 부담 합계 = 양식 입력 합계 + 대상 외 직원분 + 미반영(확인 대상)분`(당월/정산 구분). 차이 0이면 ✔, 아니면 사유 목록. 고용보험은 원본 `합계` 행과 행 합산값도 대조. 부가: 건강·요양 사업주 몫 합계, 절사 차액, 확인 대상 목록, 대상 외 원본 직원 목록.

## 4. 비기능 요구사항
- **서식·값 보존**: 대상 `.xls`를 메모리에 열어 해당 8칸만 수정 후 다른 이름으로 저장(셀 스타일·열 너비·기타 열 값 유지, 입력 칸이 빈칸이면 같은 열 스타일 계승). 저장 후 자동 재오픈 비교(8칸 외 diff 0건)를 스스로 점검.
- **개인정보**: 주민번호는 매칭 검증에만 쓰고 화면·로그·보고서에는 노출/저장 안 함. 오프라인 동작, 외부 전송 없음.
- **환경**: Windows 10/11, Excel 미설치 PC에서도 동작, 설치 없이 실행되는 단일 exe.
- **오류 처리**: 파일 잠김(Excel에서 열림)·형식 불일치·헤더 변경 시 한국어 안내.

## 5. 기술 설계
- **스택 권장**: C# **.NET 8 + WPF**(MVVM, 단계형 Wizard) + **NPOI**(.xls 읽기/쓰기 HSSF, .xlsx 읽기 XSSF). 근거: 현재 PC에 .NET 6/8/10 런타임 설치됨, Excel 비의존, `.xls` 기존 서식 유지 수정이 가능. 대안(Excel COM)은 Excel 필수라 제외, Python은 미설치.
- **구조** (`Insure_flow\src\`)
  - `InsureFlow.Core` : `Readers/`(NpReader, EiReader, HiReader, TargetSheet — **헤더 문구로 열 탐색**, 고정 인덱스 금지), `Matching/NameMatcher`, `Calc/ShareCalculator`(÷2·절사), `Model/`(EmployeeRow, Cell 상태), `Validation/ReconciliationReport`, `Writers/TargetWriter`, `Writers/ReportWriter`
  - `InsureFlow.App` : WPF 4단계 화면(ViewModels/Views)
  - `InsureFlow.Tests` : xUnit
- **처리 파이프라인**: Read×4 → 정규화 → 이름 매칭(동명이인/교차검증) → 칸별 값 산출(상태 부여) → 미리보기 모델 → 사용자 확정 → TargetWriter → 재오픈 diff 검증 → ReportWriter.
- 금액 타입 `decimal`/`long`(원 단위 정수), 절사는 `Math.Truncate(x/2/10)*10` 방식으로 음수도 0 방향.

## 6. 화면 흐름 (한국어)
`① 파일 선택` → `② 입력 미리보기` → `③ 확인` → `④ 저장` (상단 단계 표시줄, 이전/다음 버튼, 다음 버튼은 조건 충족 시만 활성화)
- ①: 4슬롯 카드 + 인식 결과(✔ 국민연금 58명 …). ②: DataGrid + 필터 + 근거 패널. ③: 합계 검증표 + 확인 체크리스트. ④: 저장 경로·결과·보고서 열기.

## 7. 개발 단계
1. **M1 코어(2~3일)**: 4개 파일 리더·헤더 탐색, 계산·매칭, 콘솔 수준 검증으로 샘플 합계 재현.
2. **M2 쓰기/보고서(1~2일)**: TargetWriter(서식 보존), 재오픈 diff, 검증보고서.
3. **M3 UI(2~3일)**: 4단계 화면, 동명이인 선택 UI.
4. **M4 테스트·배포(1~2일)**: 합성 데이터(동명이인·소급·환급·누락) 단위/통합 테스트, 단일 exe 퍼블리시.

## 8. 검증 방법 (구현 후)
- 샘플 4파일로 실행 → 결과 `.xls`를 Excel로 열어 8칸 외 변경 없음·서식 동일 확인(자동 diff + 육안).
- 수기 대조 3건: 음수 환급 직원(요양 정산 −), 연말정산 직원(건강 +), 퇴직정산자(당월 0 / 정산분만).
- 합계: 국민연금 합 = 원본 본인기여금 합, 고용 = 원본 `합계` 행(① 2,379,530 / ③ 60,930, 대상 외·누락 사유 반영), 건강·요양 = Σ절사값 + 대상 외 직원분.
- 합성 데이터: 동명이인(자동입력 금지), 국민연금 소급 음수, 주민번호 불일치, 월 불일치, 슬롯 오배치, 잠긴 파일, 원본 덮어쓰기 시도.
- `dotnet test` 통과 + exe를 Excel 미설치 환경에서 실행.

## 9. 위험 및 열린 항목
- NPOI HSSF가 일부 고급 서식(조건부 서식·도형)을 누락할 수 있음 → 대상 양식으로 round-trip 조기 검증(M2 초반), 문제 시 Excel COM 폴백 옵션 검토.
- EDI 양식 변경(열 이름·행 구조) → 헤더 기반 탐색과 "인식 실패 열 안내"로 완화.
- 건강보험 근로자 몫의 법정 단수처리 방식이 급여 담당 관행과 다를 수 있음 → 계산 규칙을 설정 파일 1곳으로 분리해 조정 가능하게.
- 샘플 파일(주민번호 포함)은 저장소에 커밋 금지(`docs\*` .gitignore).
